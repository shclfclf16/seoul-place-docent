# MCP 기반 서울 장소 도슨트 KPI

기준일 2026-11-08. 아래 수치는 팀 협의 전 제안하는 1차 합격 목표이며 실측 성과가 아니다.

## 서비스 목표와 범위

사용자의 한국어 질문을 AI가 분류하고 필요한 MCP 도구를 선택해 공개자료를 조회한 뒤, 사진과 출처가 연결된 짧은 답변을 제공한다.

처리 순서는 질문 → 의도·장소 범위 분류 → 주소 후보 확인 → MCP 조회 → 근거 대조 → 답변 또는 추가 질문이다.

현재 MCP 서버는 원본 파일의 EXIF GPS를 읽는 `extract_photo_location`, 실제 좌표를 변환하는 `resolve_photo_location`, 주소 검색·역사 조회·근거 준비·기계 검증·통계를 제공합니다. `prepare_place_answer`와 호환 이름 `generate_place_answer`는 근거 묶음만 반환합니다. 서버는 분류·해설 생성을 위해 모델 API를 호출하지 않습니다. 질문 분류와 최종 해설은 호출한 사용자의 AI가 수행합니다.

최종 KPI는 **스마트폰 원본 파일 첨부 → 실제 GPS 추출 → 한국어 주소 확인 → 사진·영상·출처를 포함한 AI 도슨트 완수**입니다. 단계별 계획·기기별 표본·실측 산식은 [사진 MCP 실행 계획](photo-mcp-execution-plan.md)을 기준으로 합니다. 원본 파일 전달은 호스트의 파일 입력 지원과 GPS 보존 여부를 따로 검증해야 합니다.

`get_answer_stats`는 서버에서 관측한 근거 조회·기계 검증 통계만 반환합니다. 최종 답변 완료, 사실의 의미적 정확도, 실제 이미지 표시, 사용자 토큰은 자동 측정하지 못합니다. 다음 목표는 실측 성과가 아니며 수동 평가·도구 trace를 함께 사용합니다.

## 분류 기준

| 라벨 | 의미 | 필요한 동작 |
| --- | --- | --- |
| address_lookup | 주소나 장소 후보 찾기 | search_place |
| history_story | 장소·동네의 역사 설명 | 주소 미확정 시 search_place, 확정 후 get_place_history |
| visual_records | 옛 사진·지도 등 시각자료 | get_place_history의 photos와 evidence 사용 |
| evidence_lookup | 설명의 근거·원문 확인 | get_place_history의 evidence 사용 |
| archive_stats | 자료 수와 DB 현황 | get_archive_stats |
| clarification_or_unsupported | 불명확·서울 외·지원하지 않는 요청 | 추가 질문 또는 지원 범위 안내 |

복합 질문에는 필요한 라벨을 여러 개 지정할 수 있다. 분류기는 의도, 입력 주소, 대상 범위(place/neighborhood/district), 시기, 추가 확인 필요 여부를 구조화해 반환하도록 설계한다. 임의의 자체 신뢰도 점수만으로 정답 여부를 판단하지 않는다.

주소 후보가 여러 개면 확인 질문을 한다. 사용자가 주소를 고르면 search_place에서 받은 유효한 token을 조회에 사용한다. 동네 사진을 개별 건물의 사진으로 승격하지 않는다. 현 데이터의 개별 건물·부지 직접 연결 상태는 unverified다.

## 1차 KPI

| 구분 | 지표와 산식 | 합격 목표 | 측정 방법 |
| --- | --- | --- | --- |
| 호스팅 | 정상 MCP 호출 수 / 스키마가 유효하고 권한이 있는 호출 수 | 99% 이상 | 7일 이상, 1,000회 이상. 도구 isError도 실패로 계산하고 제공기관 장애를 별도 표시 |
| DB | D1 통계 조회 성공 수 / 통계 조회 시도 수 | 99% 이상 | 유효 요청 100회 이상. 데이터 건수 0도 정상 값이면 성공 |
| 분류 | 의도별 precision·recall의 조화평균을 라벨별 평균한 macro F1 | 0.90 이상 | 고정 홀드아웃 200문항 이상, 라벨별 점수와 표본수 함께 보고 |
| 공간 범위 | place/neighborhood/district 범위 정답 수 / 범위 평가 문항 수 | 95% 이상 | 정답 데이터에 명시한 범위와 비교 |
| 도구 선택 | 필요한 순서·도구·필수 인자를 모두 충족한 문항 수 / 도구 평가 문항 수 | 95% 이상 | AI 실행 trace를 정답 경로와 비교. 불필요한 생성 호출도 기록 |
| 검색 | 정답 근거가 상위 5개 반환 장면에 포함된 문항 수 / 관련 근거가 실제 수록된 문항 수 | Recall@5 0.85 이상 | 근거가 없는 문항을 분모에서 제외하고 제외 수 공개 |
| 근거 충실도 | 연결된 근거로 지지되는 사실 주장 수 / 전체 사실 주장 수 | 95% 이상 | 두 명이 문장 내 주장 단위로 판정하고 불일치를 합의 |
| 출처 표시 | 유효한 기관·원문 링크가 연결된 사실 주장 수 / 전체 사실 주장 수 | 100% | 링크 존재와 실제 지지 여부를 별도로 검사 |
| 잘못된 부지 연결 | 동네·자치구 근거를 개별 건물·부지 사실로 단정한 건수 | 평가 세트 0건 | 최소 50개 함정 문항 포함. 1건이라도 발견하면 출시 보류 |
| 미확인 처리 | 자료 없음·주소 모호함·지원 밖에서 적절히 보류·질문한 문항 수 / 해당 문항 수 | 95% 이상 | 최소 50문항. 단순 오류 메시지는 적절한 처리로 자동 인정하지 않음 |
| 답변 완수 | 정답의 필수 정보·공간 범위·출처를 충족한 문항 수 / 전체 평가 문항 수 | 85% 이상 | 정상 답변과 적절한 보류·추가 질문을 정답 기준에 따라 평가 |
| 처리시간 | 질문 제출부터 최종 답변 표시까지 p95 | 20초 이하 | 최소 200건. 실패·시간초과 비율도 함께 표시. 사람의 후보 선택 대기시간은 별도 집계 |
| AI 요청 제한 | 모델 제공자의 429·쿼터 오류 건수 / 모델 호출 시도 수 | 1% 이하 | 분류·생성 각각 집계. MCP 서버 자체 오류와 구별 |
| 비용 | 분류·생성 실제 API 비용 합계 / 완료된 답변 수 | 우선 기준선 측정 | 초기 200문항에서 모델·입출력 토큰·통화·측정일 기록 후 팀이 예산 상한 확정 |

정답이 없는 질문을 모두 답변 거절해 근거 충실도만 올리는 것을 방지하기 위해 검색·완수·미확인 처리를 함께 평가한다. MCP 호스팅 성공만으로 AI 분류·답변 성과 달성을 주장하지 않는다.

## 평가 세트와 판정

1. 서울 5개 자치구 이상과 대표 주소 10곳 이상을 포함한 고정 질문 200개를 준비한다. 의도별 최소 25개를 확보하고 복합 의도에는 복수 라벨을 부여한다.
2. 200개 중 최소 50개는 동네와 건물 혼동, 주소 중복·누락, 자료 없음, 서울 외 요청, 만료 token 등 경계 사례로 구성한다. 분류 평가와 도구 입력 검증은 별도 표로 집계한다.
3. 문항마다 기대 의도, 기대 범위, 확인 질문 필요 여부, 허용 도구 순서, 관련 자료 ID·원문 URL, 필수 답변 요소를 두 사람이 확정한다.
4. 개발·프롬프트 조정용 질문은 홀드아웃과 분리한다. 홀드아웃을 조정에 사용하면 새 평가 세트와 버전을 만든다.
5. 모델·프롬프트 버전과 데이터 커밋을 고정해 실행하고 confusion matrix, 문항별 실패 사유, 표본수를 보관한다.
6. 수동 원문 평가가 없는 자동 점수는 보조 지표로 표시한다. 표본 0개 또는 관측이 없으면 0%나 100% 대신 미측정으로 표시한다.

## 측정 기록 항목

question_id, dataset_version, data_commit, classifier_model, classifier_prompt_version, expected_intents, predicted_intents, expected_scope, predicted_scope, requires_clarification, selected_tools, tool_success, tool_latency_ms, end_to_end_latency_ms, retrieved_scene_ids, cited_urls, supported_claim_count, total_claim_count, false_place_link_count, answer_complete, abstention_correct, provider_error_code, input_tokens, output_tokens, api_cost, cache_source, reviewer_ids.

운영 지표에는 요청 ID·시간·도구·상태·지연시간을 기록한다. 질문 원문·정확한 주소·주소 token·API 인증 키를 기본 로그에 저장하지 않는다. 평가 데이터는 팀이 작성한 공개 장소 질문을 사용한다. 현재 서버는 mcp_tool_call_log와 mcp_client_docent_log에서 도구 호출·근거 조회·기계 검증 상태를 기록한다(질문 원문·주소·원본 사진·첨부 URL은 저장하지 않음). 나머지 항목은 첫 평가에서 테스트 클라이언트 실행 기록과 수동 채점으로 진행한다.

## 호스팅 완료 조건

- Sites 배포 성공과 MCP 연결 정보 반환
- server/discover 및 tools/list 정상 응답
- 주소 검색 → 확인된 후보 token → 역사·사진·근거 조회 성공
- get_archive_stats의 실제 D1 조회 성공
- 잘못된 token·잘못된 도구 인자에 안전한 오류 반환
- 별도 AI 클라이언트의 자연어 질의 성공은 연결 후 따로 확인

## 발표용 목표 문장

서울 역사자료 조회 기능을 MCP 서버로 호스팅하고, AI의 질문 의도 분류 macro F1 0.90 이상, 근거 충실도 95% 이상, 출처 표시율 100%, 잘못된 건물·부지 연결 0건을 목표로 주소 기반 역사 답변 서비스를 평가한다.

현재 값과 검증 결과는 배포·평가 실행 후 기록한다. 이 문서의 목표값은 성능 측정 결과가 아니다.
